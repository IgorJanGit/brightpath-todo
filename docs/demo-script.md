# Demo video script (target ≈ 4 minutes)

Talking points, not a script to read word for word. Have these tabs open before recording: the live app, `/health`, the architecture PNG, the deploy-flow PNG, the GitHub Actions run list, and the AWS console (EC2 security group + Billing/Budgets).

---

## 1. It works (≈ 40 s)

- Open the live link. Point out the HTTPS padlock.
- Add two to-dos, tick one off, delete one, then **refresh the page**: "these are coming back from PostgreSQL on RDS, not from the browser."
- Open `/health`: "200, app OK, database OK with latency, and it tells me which git commit and which EC2 instance is serving."
- *(Optional, strong)* Show the GitHub Actions run for the latest push and that `version` in `/health` matches the commit SHA.

## 2. Architecture walkthrough (≈ 90 s)

Use `docs/architecture.png`, following the numbers:

> "The browser resolves an sslip.io name that maps to my Elastic IP, comes in through the internet gateway, and hits a t3.micro running Amazon Linux 2023. Only ports 80 and 443 are open. Caddy terminates TLS and proxies to the Flask container over Docker's internal network. The app talks to RDS Postgres in a private subnet with no internet route, over TLS, and the database's security group only accepts traffic from the web server's security group."

Then one sentence per choice, each with the alternative:

- **t3.micro:** Free Tier on both old and new accounts. *Considered t4g.micro (ARM, cheaper), but I'd need multi-arch builds.*
- **Amazon Linux 2023:** SSM agent and AWS CLI built in. *Ubuntu would work too; AL2023 meant less setup.*
- **RDS Postgres:** managed backups, patching, encryption, private endpoint. *Considered Postgres in a container on the same box: cheaper, but data tied to one 1 GB server.*
- **Traffic:** Elastic IP + Caddy for free HTTPS. *Considered an ALB with ACM, which is what I'd do with real traffic, but for one instance it adds cost and needs a domain.*

Flip to `docs/deploy-flow.png` (≈ 20 s): push → tests → image to ECR → SSM Run Command → `compose up --wait` with automatic rollback → smoke test on `/health`. "No SSH and no AWS keys in GitHub; it uses OIDC."

## 3. Security and cost (≈ 45 s)

Show the EC2 security group (80/443 only) and the RDS SG (5432 from the web SG only).

- Secrets: generated by Terraform → SSM SecureString → root-only file on the box. `.gitignore` covers state and env files. "There's nothing secret in this repo."
- IMDSv2 required, encrypted disks, least-privilege IAM roles.
- Cost: Free Tier instance types, 20 GB RDS, no NAT Gateway (≈ $32/month avoided), ECR lifecycle policy, logs kept 7 days, CPU credits set to standard so no burst charges. A $5 Budget with credits excluded, plus `terraform destroy` to remove everything.

## 4. Something that went wrong (≈ 40 s)

**Use your own real incident.** Structure: *symptom → what I checked → actual cause → fix → how I'd catch it sooner.* Reviewers specifically want to hear that you found the root cause rather than working around it.

Things that commonly bite on this exact setup, so you'll recognise them if they happen (only talk about one if it actually happened to you):

| Symptom | Where to look | Typical root cause |
|---|---|---|
| `/health` → 503, `database.error: "PoolTimeout"` | `aws logs tail /todo/app` | DB SG not referencing the web SG, wrong host in SSM, or `sslmode` mismatch (RDS PG 16 forces TLS) |
| Site loads on `http://IP` but HTTPS fails | Caddy logs in the `/todo/app` log group | Port 80 blocked (Let's Encrypt HTTP-01 challenge needs it) or rate limits |
| Deploy step: `AccessDenied` on `AssumeRoleWithWebIdentity` | Actions log | `github_repo` case/typo doesn't match the OIDC `sub` claim, or the workflow isn't running on `main` |
| SSM command stuck in `Pending` / instance not in Fleet Manager | Systems Manager → Fleet Manager | Instance had no internet yet (EIP not attached) or the role lacked `AmazonSSMManagedInstanceCore` |
| `terraform apply`: `FreeTierRestrictionError` on RDS | Terraform output | Backup retention > 1 day on a Free Tier account |
| Deploy rolled back | SSM command output shows the last app logs | New image failing its health check (that's the safety net working) |

## 5. Before real customers (≈ 30 s)

Pick the top three from the README: **ALB + Auto Scaling across two AZs + RDS Multi-AZ** (no single points of failure), **a real domain with ACM and WAF**, and **a staging environment, remote Terraform state and proper DB migrations**. Close with: "then metrics and alerts on what users feel, such as error rate and latency, not just whether the host is up."
